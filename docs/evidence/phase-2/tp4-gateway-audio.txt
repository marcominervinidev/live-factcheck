Found on the way (second occurrence of "tests green, runtime lacks a dependency")
  The stack showed the gateway crashing at start: `ws` was only a devDependency (used by tests
  before), so the runtime image did not have it. Fixed, and made automatic instead of a written
  rule (AGENTS.md, learning from mistakes):
  - dependency-cruiser rule `not-to-dev-dep-in-production` (production code of services and
    packages must not import devDependencies; type-only imports allowed)
  - the configuration excluded node_modules completely, so npm rules never fired; npm packages
    are now included as leaves (299 modules instead of 275)
  - negative test: with ws moved back to devDependencies the rule reports
    `services/gateway/src/audio.ts → node_modules/.pnpm/ws@8.21.3/…/ws/wrapper.mjs`; with the fix
    "no dependency violations found"
  Stage 3 test adjusted: in the real stack backpressure or the rate limit fire first depending on
  timing; the test checks the purpose (overloaded), the exact code stays in stage 2a.
